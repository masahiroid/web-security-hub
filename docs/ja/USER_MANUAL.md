# Web Security Hub 利用マニュアル

[English version](../USER_MANUAL.md)

> 初めての方は [実画面付きハンズオン](../training/README.ja.md) から始めてください。基本コースと応用機能の対応は [機能対応表](../training/COVERAGE.md) にまとめています。

## 1. 目的

Web Security Hub は、フォーム回帰テストと Web アプリケーション脆弱性診断を同じ対象サイト・認証設定・テストシナリオで実行するローカルツールです。テストケースの値生成とスキャンはルールベースです。Claude Code を使う SAST レビューと自然言語アサーションは、明示的に有効化する任意機能です。

主な用途は次のとおりです。

- HTML フォームを巡回し、正常・境界・異常値を含むテストケースを生成する。
- 生成した Playwright テストを再実行し、画面差分を確認する。
- Playwright で到達した画面・通信を ZAP に渡し、既存の脆弱性検査ルールで診断する。
- ローカルソースを静的解析する。

## 2. 起動

```sh
npm install
npm start
```

ブラウザーで `http://localhost:4173` を開きます。`EADDRINUSE` が出る場合は、既に起動済みのため同じ URL を開くか、既存サーバーを停止してから再起動します。

ZAP 統合を使う場合は別途起動します。

```sh
docker compose -f docker-compose.zap.yml up -d
```

初回はコンテナイメージの取得に時間がかかります。終了時は次を実行します。

```sh
docker compose -f docker-compose.zap.yml down
```

## 3. サイト管理

1. **サイト管理**タブでサイト ID、表示名、起点 URL を入力します。
2. 巡回の最大深さ、最大ページ数、フォームあたりの最大ケース数を設定します。
3. ログインが必要なら URL、入力欄セレクタ、送信ボタンセレクタ、認証情報を設定します。
4. 保存します。

認証情報は `sites/<siteId>/.env` に保存され、画面には再表示されません。テスト専用アカウントを使用してください。

### 保存済みシナリオ

**保存するシナリオ**には、`steps` を持つ JSON オブジェクトを保存します。基本操作は `goto`、`click`、`fill`、`check`、`select`、`wait` で、最大 50 ステップです。ナビゲーション、ファイル操作、分岐・繰り返しなどの拡張は [README](../../README.ja.md) と [機能対応表](../training/COVERAGE.md) を参照してください。この JSON に認証情報を含めないでください。ログイン用セレクタはサイト管理に保存し、認証情報は `.env` に保持されます。

保存済みシナリオはテストケース生成で使用され、生成される Playwright 再実行 spec にも引き継がれます。**動的脆弱性診断**では「選択中サイトの保存済みシナリオを使用する」を選ぶと、認証情報をブラウザー UI に表示せずに同じ認証済みフローを実行できます。

### Playwright で操作を記録する

1. ログイン用セレクタとテストアカウントを含めてサイトを保存・選択します。
2. **Playwright 操作記録**で対象を操作・診断する許可を確認し、「記録用ブラウザーを開く」を選びます。
3. 可視の Chromium が開きます。サーバー側の `.env` 認証情報で設定済みログインを先に実行した後、許可された導線を操作します。
4. 「記録を停止してシナリオへ反映」を選び、生成された JSON を確認してから「保存」します。

クリック、選択変更、チェック、直接の画面遷移を記録します。パスワードおよびセレクタ名から認証情報・トークン・秘密情報と判断できる欄は記録しません。パスワード以外の入力値も、明示的なチェックを有効にした場合だけ記録します。保存前にセレクタと値を確認し、個人情報や機微な値を削除してください。保存したシナリオはテストケース生成、再実行、認証済み DAST のすべてで利用できます。

## 4. テストケース作成

**テストケース作成**タブで「パイプラインを実行」を選びます。

処理内容は、サイト巡回、フォーム抽出、HTML 制約に基づく候補値の作成、ペアワイズ組合せ、Playwright spec の生成です。作成される成果物はサイトごとの `.golden-master/session-<日時>/` に保存されます。

| 成果物 | 内容 |
|---|---|
| `forms.json` | 発見したフォーム・フィールド・制約 |
| `test-cases.json` | 生成ケース |
| `test-cases.yaml` | 人手編集可能なケース定義 |
| `generated.spec.ts` | Playwright の再実行用 spec |
| `report.html` / `report.md` | テスト生成・実行レポート |

生成値はルールベースです。HTML の `required`、`min`、`max`、`maxlength`、`pattern`、フィールド型、ラベル等を利用し、正常・境界・異常値を作ります。

## 5. テストケースの編集・再実行

1. **再実行**タブでセッションを選択します。
2. 「読み込む」で YAML のケースを表形式で開きます。
3. 必要な入力値を修正し、「保存して再生成」を選びます。
4. 初回は「ベースラインを記録」、以後は「再実行（比較）」を選びます。

比較先 URL を入力すると、同じ spec を別環境に対して実行できます。

## 6. ZAP とテストケースを結合する

1. ZAP を起動し、**動的脆弱性診断**タブの「ZAP 接続を確認」で接続できることを確認します。
2. **再実行**タブで「このテストケース実行の全通信を ZAP に送る」を有効にします。
3. 回帰テストを実行します。
4. ZAP の Alert はセッションの `zap-alerts.json` に保存されます。Alert に紐付けられる場合は `testCaseIds` にテストケース ID が入ります。

「ZAP アクティブ検査も実行する」は、明示的な許可を得たステージング環境だけで使用してください。許可確認チェックなしには実行できません。

既存セッションを ZAP 統合で使う場合、先に「テストケースを編集」から保存して spec を再生成してください。

## 7. 動的脆弱性診断

開始 URL、巡回範囲、必要なら認証・シナリオ JSON を設定して実行します。パッシブ診断では HTTPS、セキュリティヘッダー、Cookie 属性、Mixed Content、フォーム構成を確認します。ZAP を有効にすると、ZAP の Passive / Active Scan Rules も利用できます。

シナリオ JSON の例:

```json
{
  "login": {
    "url": "https://staging.example.test/login",
    "usernameSelector": "#email",
    "username": "tester@example.test",
    "passwordSelector": "#password",
    "password": "test-password",
    "submitSelector": "button[type=submit]"
  },
  "steps": [
    { "action": "click", "selector": "a[href='/settings']" },
    { "action": "fill", "selector": "#search", "value": "sample" }
  ]
}
```

基本アクションは `goto`、`click`、`fill`、`check`、`select`、`wait` です。拡張アクションは README を参照してください。認証情報やシナリオ本文は保存されず、診断結果にも含めません。

## 8. 静的解析

**静的解析**タブでローカルソースの絶対パスを指定します。`node_modules`、`.git`、`dist`、`build`、`coverage` は除外されます。現時点では動的コード実行、コマンド実行 API、SQL 文字列連結、秘密情報形式、TLS 検証無効化を検出します。

各実行はローカルの `artifacts/static-scans/<run-id>/` に保存されます。画面から JSON、HTML、Markdown、SARIF レポートを開けます。レポートにはソースディレクトリ、実行時刻、解析ファイル数、重要度集計、検出結果を記録するため、診断証跡として保管したり、SARIF 対応ツールへ取り込んだりできます。`artifacts/` は Git の管理対象外です。

### Claude Code による任意の AI レビュー

静的解析の実行後、**Claude Code による AI レビュー**からローカルの Claude Code にレビューを依頼できます。この機能は任意であり、利用者自身の契約で Claude Code をインストールしてログインしている必要があります。レビューのたびに、表示中の SAST 結果を送信する明示的な許可を確認します。

アダプターが送るのは、SAST の集計と検出メタデータ（ルール ID、重要度、場所、根拠、修正案）に限ったサイズ制限付きのレビュー用パッケージです。ソース本文、認証情報、API キーは送信せず、Claude Code はプロジェクトディレクトリではなく一時ディレクトリから起動します。AI の回答は補助的な意見であり、脆弱性や修正方針として扱う前に必ず人が確認してください。

`ANTHROPIC_API_KEY` が存在する場合は、API 課金よりローカルの Claude 契約ログインを優先するため、Claude Code の実行環境から除外します。

## 9. 安全な運用

- 自組織または書面で許可を受けた対象だけを診断してください。
- アクティブ検査は本番環境ではなく、テストデータだけを含むステージング環境で実行してください。
- 削除、解約、退会、決済など不可逆な導線は巡回範囲から外してください。
- 認証用アカウントには最小権限を与え、個人情報を持たせないでください。
- 検出結果は人が確認してからチケット化・修正判断してください。
