# Web Security Hub 詳細設計書

[English version](../DETAILED_DESIGN.md) · [仕様書](SPECIFICATION.md) · [設計書](ARCHITECTURE.md) · [画面設計書](SCREEN_DESIGN.md)

設計書で示した構成要素ごとに、処理の手順、規則、状態、データ項目、エラー時の扱いを示します。

## 1. サイト設定

### 1.1 データ項目

| 項目 | 型 | 内容・制約 |
|---|---|---|
| 識別子 | 文字列 | 英数字・ハイフン・アンダースコア。保存先の名前になる。必須 |
| 表示名 | 文字列 | 画面表示用 |
| 起点 URL | URL | 巡回の開始位置。モバイルでは使わない |
| プラットフォーム | 選択 | web／ios／android。既定は web |
| 巡回 | 設定 | 最大深さ、最大ページ数、フォームあたり最大ケース数、正常値だけのペアワイズ、ドライラン、可視ブラウザー、早期失敗、成功の目印 |
| ログイン | 設定 | ログイン URL、ユーザー名・パスワード・送信ボタンのセレクター（資格情報は含めない） |
| Basic 認証 | 設定 | 使用有無（資格情報は含めない） |
| ブラウザー | 設定 | エンジン（Chromium／Firefox／WebKit）、端末名、クライアント証明書の origin と相対パス |
| 変数 | 連想 | 標準変数。シナリオ内で名前参照できる |
| シナリオ | 設定 | 巡回・実行の前に再生するステップ列と、繰り返し用のデータセット名 |
| シナリオ展開 | 配列 | 宣言的なケース展開の定義 |
| モバイル | 設定 | 端末名、OS バージョン、アプリのパスまたはバンドル ID |
| グループ・ラベル | 文字列・配列 | 整理用 |
| AI アサーション | 設定 | 有効化の有無と言語。既定は無効 |

### 1.2 規則

- 保存時に、設定全体をスキーマで検証し、未知の項目や範囲外の値は拒否する。
- 資格情報は、設定ファイルとは別の秘密情報ファイルに保存する。応答に値を含めず、設定済みかどうかだけを返す。
- 設定内の相対パスは、サイトのフォルダーの内側に解決し、外側を指すものは拒否する。

## 2. テストケース生成

### 2.1 手順

1. 設定と秘密情報から実行設定を組み立てる。シナリオがあれば先に再生してログイン済みにする。
2. 起点から、同一オリジンのリンクを幅優先で辿る。最大深さと最大ページ数を超えない。
3. 各ページのフォームと入力欄を抽出し、型・必須・長さ・範囲・選択肢・ラベルと、安定したセレクターを取得する。
4. 入力欄ごとに候補値を作る（2.2）。
5. 候補値をペアワイズで組み合わせ、フォームあたりの最大ケース数に収める。
6. セッションに、フォーム一覧、URL 一覧、ケース、テストコード、YAML、レポートを保存する。

### 2.2 候補値の規則

| 入力欄の種類 | 正常 | 境界 | 異常 |
|---|---|---|---|
| 選択肢（セレクト・ラジオ） | 文脈に合う有効な選択肢 | 最後の有効な選択肢 | 選択肢に存在しない値 |
| チェックボックス | オン | オフ | — |
| 数値・範囲 | 範囲の中央 | 最小・最大 | 範囲外 |
| 文字列 | ラベルや種類から推定した妥当な値 | 最小・最大の長さ | 長さ超過、空、特殊文字 |
| 日本語の住所・電話・かな | 一般的な形式の既定値 | 桁数の境界 | 形式違反 |

- 値は HTML の制約、入力の種類、ラベルなどの決定論的な規則だけで作る。同じ入力から同じ値になる。
- 同じ値は重複を除く。値には、その理由を付ける。

## 3. 再実行と比較

- ベースラインの記録: セッションのテストコードを実行し、各画面の状態を基準として保存する。
- 再実行: 基準と同じケースを実行し、画素単位で比較する。差分があれば失敗とし、差分画像と結果を比較レポートに保存する。
- 比較先 URL を指定した場合、同じケースを別の環境に対して実行する。
- ZAP の併用では、全通信をプロキシ経由にし、ケースごとの識別ヘッダーを付ける。アクティブ検査は、許可の確認がなければ実行しない。

## 4. シナリオ実行

### 4.1 ステップの種類

| 種類 | 動作 |
|---|---|
| goto | 指定 URL へ移動 |
| click／fill／check／uncheck／select | 要素の操作・入力・選択 |
| wait | 時間または要素を待つ |
| back／forward／reload | 履歴の移動・再読み込み |
| setFile | サイトの専用フォルダー内のファイルをアップロード |
| download | ダウンロードをサイトの専用フォルダーへ保存 |
| branch | 要素の有無・表示・テキストで分岐 |
| loop | 指定回数の繰り返し |
| useSharedStep | 共有ステップ群の展開 |
| aiAssert | 自然言語の期待の確認（有効にしたサイトのみ） |

- ステップは実行前に検証し、未対応の種類や不正な値は拒否する。
- 値には、標準変数・秘密変数を名前で参照できる。秘密変数の値は結果に出さない。
- データセット（CSV）を指定すると、1 行ごとにシナリオを繰り返す。
- テスト生成と動的診断は、同じ実行器を使うため、動作が一致する。生成するテストコードにも同じ動作を持たせる。

### 4.2 ロケーターの自己修復

- 記録時に、各操作に構造情報（タグ、ID、テスト用属性、名前、役割、ラベル、プレースホルダー、テキスト、クラス）を保存する。値は保存しない。
- 実行時に、主セレクターが数秒以内に見つからなければ、構造情報から作った候補を順に試し、なければ同じタグの要素を一致度で採点して最も近いものを使う。
- 修復は必ずログに記録し、結果に集める。黙って置き換えない。

### 4.3 シナリオ記録

- 保存済みのサイトと許可の確認を条件に、可視ブラウザーを 1 セッションだけ起動する。
- サーバー側の資格情報で設定済みのログインを実行したあと、利用者の操作を移植可能なステップに正規化する。
- パスワードの入力は常に除外する。その他の入力値は、利用者が別に選んだときだけ含める。
- 停止すると、ステップを画面へ返す。サイト設定として保存されるのは、利用者が保存したときだけ。

## 5. 動的診断（DAST）

### 5.1 手順

許可の確認 → シナリオの再生（任意）→ 同一オリジンの巡回 → 通信の収集 → ページごとのパッシブ検査 → 結果の集計

- 収集した通信は重複を除く。フォームの送信や侵入の試行は行わない。
- アクティブ検査は、有効化と許可の両方があるときだけ、ZAP に依頼する。

### 5.2 パッシブ検査の項目

| 検査 | 重要度 | OWASP 分類 |
|---|---|---|
| Content-Security-Policy の欠落 | high | A05 |
| HTTPS を使用していない | high | A02 |
| Strict-Transport-Security の欠落 | medium | A02 |
| X-Frame-Options の欠落 | medium | A05 |
| Secure 属性のない Cookie | medium | A02 |
| 混在コンテンツ | medium | A02 |
| X-Content-Type-Options の欠落 | low | A05 |
| Referrer-Policy の欠落 | low | A05 |
| Permissions-Policy の欠落 | low | A05 |
| パスワードフォームの GET 送信、認証フォームの CSRF 対策の確認、インラインのイベントハンドラー | 状況による | 状況による |

各検出は、識別子、題名、重要度、OWASP 分類（名前と参照先）、場所、根拠、修正案を持つ。

## 6. ZAP 連携

- 到達確認: 指定した API の URL に対し、バージョンの取得などで接続を確かめる。API は localhost のみを想定する。
- 通信の経路: 診断ブラウザーのプロキシを ZAP に向け、ケースごとの識別ヘッダーを付ける。
- 警告の取得と対応付け: 警告を取得し、警告の URL と、履歴に残った識別ヘッダーでケースに対応付ける。結果は警告とケース ID の組として保存する。
- 分類: ZAP の警告は CWE・WASC を返すため、単一の OWASP 分類へ割り当てず「要確認」とする。

## 7. 静的解析

### 7.1 手順

1. 指定ディレクトリが読み取り可能な実在するフォルダーか確認する。
2. 対象の拡張子の、大きさが 1 MiB 以下のファイルを、最大 3,000 件まで集める。依存パッケージのフォルダー、バージョン管理のデータ、ビルド成果物は除く。
3. ファイルごとに規則を当て、一致した位置を記録する。
4. 各検出に、個別の識別子、ファイルの SHA-256、文字単位の範囲、行番号を付ける。
5. 結果を重要度別に集計し、JSON・HTML・Markdown・SARIF で保存する。

### 7.2 規則

| 規則 | 重要度 | OWASP 分類 |
|---|---|---|
| 動的コード実行 | high | A03 |
| コマンド実行 API の参照 | medium | A03 |
| SQL 文字列連結の疑い | high | A03 |
| ハードコードされた秘密情報の疑い | high | A02 |
| TLS 証明書検証の無効化 | high | A02 |

### 7.3 ルートの対応付け

- 同一ファイル内の Express のルート定義を構文解析し、検出がどのルートの処理内にあるかを候補として示す。
- 複数のルートで共有される処理は「複数候補」、動的な登録や未対応の構文は「対応付け不能」と表示する。
- 候補は、実行の許可や到達の証拠にはしない。

## 8. 検証基盤

### 8.1 許可（スコープ）

| 項目 | 内容 |
|---|---|
| 対象 | origin とポート。数値の loopback のみ |
| 経路・メソッド | 許可した 1 つの経路と HTTP メソッド |
| フィールド | 送ってよい項目の一覧 |
| 認証プロファイル | 事前に登録した識別名のみ。実際の資格情報は渡さない |
| ソースの場所 | 照合に使う読み取り専用のルート |
| 期限・試行数・並行数 | 期限、試行の上限、同時実行数 |

許可は、作成時に検証し、期限切れ・取消・上限超過・範囲外への差し替え・リダイレクトを拒否する。

### 8.2 試行の流れ

1. 許可から 1 試行分の権限を取得する（上限を消費する）。
2. 認証プロファイルごとの準備手順を、独立した通信の文脈で実行する。
3. 正常対照を送る。期待した応答でなければ停止し、候補は送らない。
4. 候補を送る。リダイレクトは追わない。
5. サーバー側の観測を取得し、5 つの識別子とソースの識別子で、この試行のものだけを採用する。
6. 試行の前後でソースの識別子を確認し、変更があれば証拠を無効にする。
7. 判定する（8.4）。
8. 通信の文脈を閉じる。取消・期限・timeout でも必ず閉じる。

### 8.3 観測と相関

- 観測は、サーバーの要所（防御の直前、処理の確定の直前など）で、イベントとして記録する。
- 各イベントは、ジョブ・試行・seed・リクエスト・認証プロファイルの 5 つの識別子と、ソースの識別子を持つ。
- 計測がない場合は「未計測」、ソースの識別子が合わない場合は証拠を採用しない。到達・遮断・未計測の 3 状態を区別する。

### 8.4 判定

| 判定 | 条件 |
|---|---|
| 違反を再現 | 独立した業務規則に違反する状態を、結び付いた観測で確認できた |
| 試行範囲で違反なし | 正常対照が成功し、観測が有効で、違反を確認できなかった |
| 調査中 | 計測なし、正常対照の失敗、観測の不一致、timeout、取消、ソースだけの結果など、判断できない |

- 判定は、HTTP ステータスや評価値ではなく、独立した業務規則（例: 所有者以外が確定できてはならない）で行う。
- 「試行範囲で違反なし」は安全の証明ではない。

### 8.5 ジョブの状態

```text
開始 → 実行中 → 完了／取消／期限／試行上限／正常対照の失敗／ソースの変更／timeout／エラー
```

- 同時に実行できるジョブは 1 つ。保持するジョブは最大 8 件で、古い完了済みのものから破棄する。
- ジョブは、開始した本人のセッションだけが参照・取消できる。

### 8.6 報告

- 設定、候補、観測、判定、停止理由を JSON に、同じ内容をスクリプトを含まない HTML に保存する。
- 保存は一時領域に書いてから確定する。大きさに上限がある。

## 9. ソース検証

| モード | 内容 |
|---|---|
| 専用サンプル | 同梱サンプルのソースを解析し、ルートと許可先を照合して、正常対照と候補を送る |
| 許可した対象 | 解析済みの検出から、一意なルートだけを選ぶ。許可した loopback の API に、匿名で正常対照と候補を送る |

- 入力値は JSON のオブジェクトで、正常対照の値、候補の値、正常対照で期待する応答の項目と HTTP ステータスを指定する。
- 送信の前と後で、ソースを再読み込みして識別子を照合する。変更があれば警告を無効にする。
- 結果は「調査中」。ソースの読み直しは、実行中のコードとの同一性を証明しない。
- ZAP 環境を使う場合は、試行ごとに専用のセッションを作り、受動警告を試行に結び付け、終了時にセッションを回収する。警告は脆弱性の確定に使わない。

## 9A. ZAP 環境の導入と実行

- 導入: 固定した版の ZAP と Java を、公式の配布元から取得し、大きさと SHA-256 を検証して、利用者のデータ領域に展開する。取消ができる。
- 実行: アプリ専用のプロセス・ホーム・セッションで起動する。既存の共有 ZAP には触れない。API は読み取りを中心に使う。
- 回収: 取消・終了・親プロセスの異常終了のいずれでも、起動したプロセスとセッションを回収する。

## 10. サンプル検証

### 10.1 サンプル

- 同梱の架空データのサーバー。本人 A・B、管理者、未認証の 4 つの役割があり、記録の参照・確認・完了と、境界値の入力を持つ。
- 3 状態: 正常版、問題を入れた版（確認の飛ばしなど 4 件の違反を含む）、修正版。
- 実行ごとに状態を初期化し、ビルドの識別子（ソースの SHA-256）を持つ。

### 10.2 候補の作り方

- 乱数 seed から決定論的に、候補の順序を決める。
- 検証項目ごとの候補: 境界値・Unicode（長さ、正規化の違い、欠落項目、補助平面の文字）、所有権（本人・他人・管理者・未認証）、確認から完了への遷移（確認ありと確認の飛ばし）。
- 同じ内容は、役割を保ったまま重複を除く。上限を超える分は切り捨てる。

### 10.3 実行と停止

- 候補を順次、正常対照つきで実行する。試行数・時間・候補数の上限、取消、正常対照の失敗、ソースの変更で止まり、停止理由を記録する。

## 11. 遺伝的探索

### 11.1 個体と遺伝子

- 遺伝子語彙: フィールドごとに、取りうる値の一覧（同じ型）と、省略を許すかを定める。省略と null は区別する。
- 個体: 遺伝子の値の組、識別子、世代、親の識別子、演算（初期・交叉・突然変異・移民・モデル）を持つ。
- 通信先・認証・権限は遺伝子に含めない。

### 11.2 評価

| 項目 | 内容 |
|---|---|
| 有効の条件 | 正常対照が成功し、観測が試行に結び付き、ソースの識別子が一致する |
| 評価値 | 到達の観測、計測点の網羅、新規性（これまでにない計測点）、ZAP の新しい警告を、設定した重みで合算 |
| 欠測 | 計測できない項目は 0 にせず「欠測」とする。ZAP 未完了は「未完了」 |
| 加点しないもの | HTTP ステータス、警告の繰り返し |
| 用途 | 次の世代の親を選ぶ順位付けだけ。違反の判定には使わない |

### 11.3 世代の演算

1. **親の選択**: 有効な個体から、トーナメント選択（指定の大きさ）で親を選ぶ。無効な個体は親にしない。
2. **交叉**: 確率に従い、2 つの異なる親の値を、1 点で入れ替える。両方の親が寄与するようにする。
3. **突然変異**: 確率に従い、変更できる 1 つの遺伝子を、別の値（または省略）に変える。
4. **エリート**: 評価値の上位の個体を、再実行せず観測済みの結果のまま、次の世代の親として引き継ぐ。
5. **重複の排除**: これまでに評価した遺伝子の組は、再び提案しない。次の世代で評価するのは、常に新しい候補だけ。
6. **移民**: 繁殖だけでは新しい候補が得られないとき、一定回数の試行のあと、ランダムな候補で多様性を回復する。
7. **多様性**: 新しい候補の数が、個体数 × 多様性の下限（最低 2）を満たせなければ「多様性の枯渇」として止める。
8. 乱数は、seed から決定論的に生成する。同じ seed・設定・観測からは、同じ世代が再現する。

### 11.4 停止条件

世代数の上限、改善の停滞（指定した世代数だけ最良値が上がらない）、試行の上限、多様性の枯渇、時間の上限、取消、正常対照の失敗、ソースの変更、timeout、証拠の未確認、ZAP 未完了、実行エラー。途中で止まっても、完了した分の世代は保持する。

### 11.5 試行の予約

- 1 候補につき、正常対照と候補の 2 試行を保守的に予約し、上限を超える見込みなら実行しない。
- 評価の呼び出しが取消に応じない場合も待機を打ち切り、遅れて返った結果は採用しない。

### 11.6 独立再現

- 探索の完了後、違反らしい（評価が有効で、判定が「違反を再現」の）候補を選ぶ。
- 新しいセッション（新しいサーバー、新しい許可）で、その候補だけを再実行する。
- 次をすべて満たしたときだけ「独立再現」とする: 正常対照が成功、観測が有効、ソースの識別子が探索時と同じ、ジョブが探索時と別、違反を示すイベントがある、判定が「違反を再現」。
- 満たさなければ「再現せず」または「判定不能」とする。

### 11.7 固定ルール

- フィールドごとの固定値（境界値と 2 の累乗）の組合せを、決まった順に試す。結果からは学習しない。
- 停止条件、予算、報告の形は、遺伝的探索と同じ。

## 12. 3 方式の比較

- 組合せ: 状態（既定は問題を入れた版と修正版）× 方式（固定ルール、GA、モデルが有効なら GA とモデル）× seed。固定ルールは決定論的なので、状態ごとに 1 回。
- 事前に固定した seed の集合と、同じ試行上限を使う。
- 1 回の実行から測る: 独立再現の有無、最初の再現までの試行数、到達した計測点の数、重複した候補の数、時間、token 数と費用、停止理由。
- 集計: 方式×状態ごとに、有効な実行数、再現した数、再現率、最初の再現までの試行数の中央値、平均の計測点・重複・時間、token と費用の合計、停止理由の内訳。
- 有効な実行: 世代上限・停滞・試行上限・多様性の枯渇で終わった実行。それ以外（正常対照の失敗やエラーなど）は環境要因とみなし、待機後に 1 回再試行する。なお無効なら、報告するが分母には入れない。
- 取消されたら、そこまでの結果を「未完了」として保存する。

## 13. 言語モデルによる候補供給

### 13.1 設定

| 項目 | 内容 |
|---|---|
| モード | 無効／モック／この端末のモデル／外部サービス |
| 接続先 | この端末のモデルは数値 loopback の HTTP。外部サービスは https の origin（認証情報・パス・クエリを含まない） |
| モデル名 | 接続先に渡す名前 |
| 候補の割合 | 非エリートの枠のうちモデルに任せる割合（既定 25%）。GA の交叉率・突然変異率とは別 |
| 予算 | 呼び出し回数、再試行、応答の大きさ、応答 token、token 総数、時間、費用の上限と単価 |
| 外部送信の許可 | 外部サービスのときだけ必要。API キーは環境変数の名前だけを保持する |

### 13.2 処理

1. 各世代の終わりに、モデルへ依頼できる件数（枠 × 割合）を計算する。0 なら依頼しない。
2. 渡す情報を作る: 遺伝子の語彙（項目と許可値）と、上位の個体の値・評価値・到達の観測。識別子や通信の詳細は含めない。
3. 呼び出しの前に、回数・token・費用の上限を確認する。費用は、推定した入力と最大の応答を、残額と比べる。
4. 応答を検査する: 大きさ、JSON の形、項目の過不足、型、許可値。重複は除き、違反があれば応答全体を捨てる。
5. 失敗は有限回まで再試行し、なお失敗すれば「モデルなし」の探索を続ける。理由は、固定の符号（大きすぎる、不正な形、未知の項目、値が不正、途中切れ、拒否、通信、時間、回数上限、token 上限、費用上限、空）で記録し、モデルの生の出力は記録しない。
6. 受け入れた候補は、まだ評価していない遺伝子の組だけを、GA が作った候補の前に並べ、個体数を超えない範囲で採用する。試行の上限は変わらない。

### 13.3 モック

- モデルを使わずにこの機能の動作を試すための、決定論的な代替。最良の候補の近傍の値を返す。言語モデルではない。

## 14. OpenVEX

### 14.1 データ項目

| 単位 | 項目 |
|---|---|
| ドラフト | ドラフト ID、文書 ID、版、作成者、役割、作成・更新時刻、ステートメント、レビュー（状態、承認者、承認時刻） |
| ステートメント | 脆弱性 ID、説明、製品（ID・SHA-256）、状態、根拠、理由、影響の説明、補足、対応方針、時刻、証拠 |
| 証拠 | 種別（サンプル・遺伝的探索・ソース）、レポート ID、観測（再現・再現せず・判定不能）、ソースの識別子、作成時刻 |

### 14.2 証拠の観測の導出

| 種別 | 再現 | 再現せず | 判定不能 |
|---|---|---|---|
| サンプル検証 | 完了し、再現が 1 件以上 | 完了し、再現も判定不能も 0 件 | 上記以外（取消・期限・上限・判定不能の混在） |
| 遺伝的探索 | 独立再現が成立 | 探索が正常に終わり、再現が成立しなかった（対象なしを含む） | 上記以外（取消・timeout・途中停止・判定不能） |
| ソース検証 | — | — | 常に判定不能（実行中のコードとの同一性が未証明） |

観測は、保存済みのレポートから読み直して決める。レビュー担当者が指定することはできない。

### 14.3 ステートメントの検査

1. 入力を閉じた形で検証する: 脆弱性 ID は英数字と一部の記号、製品 ID は URI 形式の文字列（パッケージ URL など）、SHA-256 は 64 桁の 16 進、説明・補足は文字数の上限内、状態・理由は定義済みの値。未知の項目は拒否する。
2. 証拠の参照は、種別とレポート ID だけを受け取り、観測はシステムが導く。存在しないレポートは拒否する。
3. 状態の規則（仕様書 4.14）を適用する。根拠が「証拠」で、証拠から導けない状態（影響なし・修正済み）は作れない。

### 14.4 承認・改訂・書き出し

- 承認: 承認者の名前が必要。ステートメントが 1 件以上あり、全証拠を読み直して、保存時の観測と同じで、規則を満たすときだけ成功する。承認後は編集・削除ができない。
- 改訂: 承認済みのドラフトから新しいドラフトを作る。文書 ID は同じ、版は 1 上がり、ステートメントを引き継ぐ。
- 書き出し: 承認済みのドラフトだけが対象。文書 ID（UUID 形式の識別子）、作成者、役割、承認時刻、版、ツール名、ステートメントを出力する。ステートメントごとに、脆弱性、時刻、製品（識別子とハッシュ）、状態、理由、影響の説明、対応方針と時刻、補足を出力する。レビュー担当者が主張した「影響なし」「修正済み」には、その旨の注記を補足に加える。
- 同じ承認済みのドラフトからは、同じ内容の文書が出力される。

## 15. 停止理由・エラー一覧

| 分類 | 理由 | 扱い |
|---|---|---|
| 完了 | 世代上限、停滞、試行上限、多様性の枯渇 | 結果を採用 |
| 利用者の操作 | 取消 | 途中までの結果を保存し、未完了と表示 |
| 期限 | 時間上限、ジョブの期限 | 途中までの結果を保存し、完了とは区別 |
| 環境・対象 | 正常対照の失敗、timeout、通信エラー | 判定不能。比較では再試行 |
| 証拠 | ソースの変更、証拠の未確認、ZAP 未完了 | 証拠を採用せず、判定不能 |
| 入力 | 不正な設定、許可範囲外、未知の項目 | 実行前に拒否 |
| モデル | 不正な応答、上限超過 | その応答を捨て、モデルなしで継続 |
