# Web Security Hub 仕様書

[English version](../SPECIFICATION.md) · [設計書](ARCHITECTURE.md) · [詳細設計書](DETAILED_DESIGN.md) · [画面設計書](SCREEN_DESIGN.md)

## 1. 目的と範囲

Web Security Hub は、利用者自身の端末で動作する Web セキュリティー診断・フォーム回帰テスト・検証ツールです。次の業務を一つの画面から行えます。

- Web アプリケーションのフォームを巡回で見つけ、正常・境界・異常の入力でテストケースを作り、繰り返し実行して変更前後を比較する。
- 許可した対象に対する動的診断（パッシブ検査、任意で ZAP との連携）と、ローカルのソースコードに対する静的解析を行う。
- 専用サンプルや許可したローカル対象に対して、正常対照つきの検証を行い、結果と証拠を非公開で保存する。
- 検証結果を根拠に、OpenVEX 文書を作成して書き出す。

### 対象外

- 利用者が所有または明示的に許可を得ていない対象への診断。
- 認証回避や DoS を目的とした検査、サービス拒否に当たる大量送信。
- 外部へ診断結果を自動送信するクラウド機能。結果は端末内に保存されます。
- 診断結果から安全性を保証すること。検出なしは、実施した試行の範囲で見つからなかったことだけを意味します。

## 2. 用語

| 用語 | 意味 |
|---|---|
| サイト | 診断対象の設定単位。識別子、起点 URL、巡回上限、ログイン情報などをまとめたもの |
| セッション | テストケース生成の 1 回分の成果物（フォーム、ケース、テストコード、レポート） |
| ベースライン | 再実行の比較元として記録した画面状態 |
| 正常対照 | 候補を送る前に、許可された正当な入力が期待どおり成功することを確かめる試行 |
| 候補 | 検証のために作る入力。本来は拒否されるべき入力を含む |
| 証拠 | 試行ごとに結び付けて取得した、サーバー側の観測、応答、ソースの識別子など |
| 独立再現 | 見つかった違反を、別のセッションで再実行して確認すること |
| ステートメント | OpenVEX 文書の 1 件の記載（製品・脆弱性・状態の組） |

## 4. 機能仕様

### 4.1 F-01 サイト管理

- サイトは識別子で区別し、識別子は英数字・ハイフン・アンダースコアに限る。表示名、起点 URL、グループ名、ラベルを設定できる。
- ログイン設定（ログイン URL と各セレクター）、Basic 認証の使用有無、保存用シナリオ、巡回上限（最大深さ、最大ページ数、フォームあたり最大ケース数。既定は 3・30・25）を設定できる。
- ユーザー名・パスワード・Basic 認証の資格情報は、サイトの秘密情報ファイルにだけ保存し、画面・レポート・結果に出力しない。保存状況は「設定済み／未設定」だけを返す。
- ブラウザーの種類（Chromium・Firefox・WebKit）、端末エミュレーション、クライアント証明書のパスを設定できる。
- 標準変数、秘密変数、共有ステップ、CSV データセットをサイトごとに管理できる。

### 4.2 F-02 テストケース生成

1. 起点 URL から同一オリジンの範囲で巡回し、フォームと入力欄の制約・安定したセレクターを抽出する。
2. 入力欄ごとに、正常・境界・異常の候補値を決定論的なルールで作る。AI は使わない。
3. 候補値をペアワイズで組み合わせ、フォームあたりの最大ケース数の範囲でケースを作る。
4. フォーム一覧、URL 一覧、ケース、テストコード、YAML、HTML・Markdown のレポートをセッションとして保存する。
- 進捗は逐次表示し、結果が保存されたセッションは再実行の対象として選べる。

### 4.3 F-03 ケース編集

- セッションのケースを YAML で読み込み、編集して保存し、テストコードを再生成できる。
- ケース群の形式が不正な場合は、エラーを返す。

### 4.4 F-04 回帰再実行

- 「ベースラインを記録」で画面状態を記録し、「再実行（比較）」で同じケースを実行して差分を確認する。
- 比較先 URL を指定すると、別の環境（修正版など）に対して同じケースを実行できる。
- 画素単位の差分を失敗として扱い、比較レポートに画像と結果を残す。
- 実行の全通信を ZAP のプロキシへ送る設定ができる。アクティブ検査を併用する場合は、許可の確認が必須。

### 4.5 F-05 シナリオ記録・認証セッション保存

- シナリオ記録: 保存済みサイトと許可確認を条件に、ローカルの可視ブラウザーを 1 セッションだけ開き、設定済みのログインを実行したあと、利用者の操作を移植可能なステップとして記録する。パスワード入力は記録しない。その他の入力値は、別の明示選択があるときだけ記録する。記録は利用者が保存するまで永続化しない。
- 認証セッション保存: SSO やサードパーティー認証が必要なアプリのため、人が手動でログインした結果（Cookie とローカルストレージ）を保存し、以降の巡回・探索をログイン済みで開始できる。第三者の認証画面そのものは自動操作しない。

### 4.6 F-06 画面探索

- 同一オリジンのリンクと、フォーム外にある破壊的に見えない操作（ボタン、タブ、ドロップダウンなど）を、独立した使い捨てのタブで一つずつ操作し、遷移後の画面を撮影して地図にする。
- フォーム内の要素、および送信・削除・ログアウト・購入などを意味するラベルの要素は操作せず「スキップ」として報告する。フォーム送信は行わない。

### 4.7 F-07 動的診断（DAST）

- 開始 URL、最大ページ数（既定 20、最大 100）、最大深さ（既定 2）、シナリオを指定して巡回し、同一オリジンの通信を収集する。
- 診断の明示的な許可がなければ開始しない。アクティブ検査は別の許可が必要で、既定では無効。
- パッシブ検査の項目（応答ヘッダーの欠落、HTTP の使用、Cookie の属性、混在コンテンツ、認証フォームの GET 送信と CSRF 対策の確認、インラインのイベントハンドラー）を検査し、重要度（high・medium・low・info）、OWASP Top 10 の分類、根拠、修正案を付けて返す。
- 診断中はフォームの送信や侵入の試行を行わない。

### 4.8 F-08 ZAP 連携

- 利用者が用意したローカルの ZAP（API は localhost のみ）へ到達できるかを確認できる。
- 有効にすると、収集した通信を ZAP のプロキシに通し、ZAP の既存ルール（パッシブ、許可があればアクティブ）で検査する。
- ZAP の警告は、URL と、ケースごとに付けた識別ヘッダーでテストケースに対応付けて保存する。警告は単一の OWASP 分類へ機械的に割り当てず、「要確認」として扱う。

### 4.9 F-09 静的解析（SAST）

- 指定したローカルのソースディレクトリを、読み取り専用で解析する。ソースは書き換えない。
- 解析対象は最大 3,000 ファイル、1 ファイル 1 MiB 以下の主要なテキスト形式。`node_modules`、`.git`、ビルド成果物は除く。
- 検査する兆候: 動的コード実行、コマンド実行 API、SQL 文字列連結、ハードコードされた秘密情報、TLS 証明書検証の無効化。
- 各検出に、個別の識別子、ソースの SHA-256、正確な位置、重要度、OWASP 分類、根拠、修正案を付ける。同一ファイル内の Express のルート候補を対応付けるが、曖昧・動的な定義は「対応付け不能」と表示し、実行の許可や到達の証拠には使わない。
- 結果は JSON・HTML・Markdown・SARIF で、解析結果専用の保存先にだけ書き込む。

### 4.10 F-10 ソース検証

静的解析の結果と、実行中のローカル対象を結び付けて検証する機能です。

- **専用サンプル**: 同梱のサンプルを解析し、ソースと許可先を照合して、正常対照と候補を送る。
- **許可した対象**: 一意なルートだけを選び、明示的に許可した数値の loopback（HTTP・指定ポート）上の JSON API に、匿名で正常対照と候補を送る。
- **入力値**: 正常対照の値、候補の値、期待する応答項目と HTTP ステータスを JSON で指定する。
- **ZAP 環境（任意）**: ZAP と実行環境を画面から導入し、試行ごとに専用セッションで受動的な証拠を集める。未導入でも通常の検証はできる。
- 正常対照が成功しない場合は候補を送らない。送信の前後でソースの変更を確認し、変更があれば証拠を無効にする。ソースだけの結果は「調査中」とし、検出や警告の有無から脆弱性・安全を確定しない。

### 4.11 F-11 サンプル検証

- 同梱の架空データのサンプルを、正常版・問題を入れた版・修正版の 3 状態で検証する。外部サイトには接続しない。
- 検証項目は「境界値・Unicode」「所有権」「確認から完了への遷移」。すべて、または個別に選べる。
- 乱数 seed、候補数上限、試行上限（正常対照を含む）、実行時間上限を指定できる。同じ seed・設定・コードでは候補の順序が再現する。
- 実行中は進捗を表示し、取消ができる。取消・期限・試行上限・正常対照の失敗・ソースの変更は、完了とは区別して表示する。
- 結果は候補ごとの判定（違反を再現／試行範囲で違反なし／調査中）と、到達の観測（到達・遮断・未計測）、証拠、HTML レポートで示す。

### 4.12 F-12 遺伝的探索

- 3 つの条件が同時にそろったときだけ違反になる架空のサンプルを、候補の選択・交叉・突然変異を世代ごとに繰り返して探索する。
- 探索の初期候補には答えを含めない。同じ候補は 2 回実行しない。各世代の上位の候補は、再実行せず観測済みの結果を引き継いで親にする。
- 候補の評価は、正常対照が成功し、サーバー側の観測がその試行に結び付いている場合だけ有効とする。評価値は次の世代を選ぶための順位付けで、違反の判定ではない。
- 違反らしい候補は、別のセッションで再実行し、独立した判定で確認できたものだけを「独立再現」とする。
- 方式は「遺伝的アルゴリズム」と「固定ルールのみ」。固定ルールは、境界値と 2 の累乗の固定リストを順に試す。
- 設定: 世代数（最大 100）、個体数（2〜64）、エリート数、選択の大きさ、交叉率、突然変異率、多様性の下限、停滞の許容世代数、乱数 seed、試行上限（最大 1,000）、時間上限（最大 3,600,000 ms）、評価の重み。
- 停止理由: 世代上限、改善の停滞、試行上限、候補の多様性の枯渇、時間上限、取消、正常対照の失敗、ソースの変更、timeout、証拠の未確認、ZAP 未完了、実行エラー。
- 任意の言語モデルが候補の一部を提案できる。モデルは初期状態で無効で、無効でも探索は完結する（4.13）。

### 4.13 F-13 3 方式の比較

- 固定ルール・遺伝的アルゴリズム・遺伝的アルゴリズムとモデルの併用を、同じ試行上限、同じサンプルの状態、事前に固定した seed の集合で比較する。モデル併用はモデルが有効なときだけ実行する。
- 測定する項目: 再現率（独立再現できた回数／有効な実行回数）、最初の再現までの試行数（中央値）、到達した計測点、重複した候補、時間、token 数と費用。
- 修正版で再現した場合は誤検知として強調する。環境要因で終了した実行は、待機後に 1 回再試行し、なお無効なら再現率の分母から除いて件数を示す。
- 結果は順位ではなく測定値で、方式の優劣は保証しない。

### 4.14 F-14 OpenVEX 作成

- 保存済みの検証結果を「証拠」として一覧し、証拠から状態を提案する。提案できる状態は、再現した結果があるときの「影響あり」と、それ以外の「調査中」だけ。
- ステートメントは、脆弱性 ID、製品 ID（パッケージ URL など。SHA-256 は任意）、状態、根拠（証拠／レビュー担当者の判断）、理由、対応方針、補足、証拠への参照で構成する。
- 状態ごとの規則は次のとおり。

| 状態 | 必要なもの |
|---|---|
| 調査中（under_investigation） | 追加の入力は不要 |
| 影響あり（affected） | 対応方針。根拠が「証拠」の場合は、再現した結果も必要 |
| 影響なし（not_affected） | 理由（定義済みの 5 種）と、根拠「レビュー担当者の判断」 |
| 修正済み（fixed） | 根拠「レビュー担当者の判断」 |

- 検証で何も見つからなかった、未観測、timeout、ZAP 未完了、ソースだけの結果からは、「影響なし」「修正済み」を作らない。この 2 状態は、レビュー担当者の主張として、その旨の注記つきで書き出す。
- 承認は名前のある承認者が行う。承認時に証拠を読み直し、結果が変わったり消えていたりすれば承認できない。承認したドラフトは編集できない。
- 変更するときは改訂版を作る。文書 ID は保たれ、版が 1 上がる。
- 書き出す文書は OpenVEX v0.2.0 形式で、文書 ID、作成者、役割、時刻、版、ツール名、ステートメントを含む。

### 4.15 F-15 モバイル診断（ソース版）

- サイト設定でプラットフォームを iOS または Android にし、端末名・OS バージョン・アプリ（またはバンドル ID）を指定すると、ローカルの Appium サーバー経由でモバイルのシナリオを実行する。
- 使える操作は、タップ、入力、待機、要素待ち、スワイプ、スクリーンショット、繰り返し。ホストに Xcode または Android SDK と、起動済みのシミュレーター・エミュレーター・実機が必要。

### 4.16 F-16 任意の AI 連携

- **AI アサーション**: シナリオの `aiAssert` ステップが、自然言語の期待を、ページのテキスト情報（表示テキストと操作要素の名前・役割）と照合する。サイトごとに明示的に有効にしたときだけ動作し、設定した外部 AI サービスへページのテキストを送ることがある。
- **AI レビュー**: 表示中の静的解析の結果だけを、明示許可のうえで、ローカルの外部 AI コマンドラインツールに渡してレビューさせる。ソース本文・認証情報・API キーは渡さない。
- どちらも既定で無効で、テストケース生成やスキャン本体では使わない。

### 4.17 F-17 デスクトップ版の開始・教材

- 開始画面で、保存先と診断ブラウザーを確認し、不足があれば画面から導入する。初回のブラウザー導入にはインターネット接続が必要。
- 日英の練習用サイトを準備し、基本版・変更版・修正版をボタンで切り替えられる。
- 画像付きのハンズオン教材を、操作中の画面から開ける。教材を開いても入力と結果は保持される。
- 画面の言語は日本語・英語・フランス語から選べる。

## 5. 外部インターフェース

アプリはローカルの HTTP サーバーとして動作し、画面はそのサーバーが提供する。外部に公開しない。

| POST | `/api/sites/:id/sessions/:sessionId/yaml/{export,regenerate}` | YAML の出力・再生成 |

## 8. セキュリティー要件

- すべての診断は、利用者が所有または明示的な許可を得た対象に限る。動的診断・アクティブ検査・ソース検証・シナリオ記録は、許可の確認なしに開始できない。
- ソース検証と検証基盤の送信先は、許可した数値の loopback の HTTP に限る。リダイレクトは追わず、許可範囲外へは送らない。
- 認証の資格情報は結果・レポート・ログに出力しない。パスワード入力は記録しない。
- 検証機能の API は、同一端末・同一オリジンの要求とセッションを必須とし、取消・状態参照は開始した本人のセッションだけに許す。
- ファイルの提供は、サイトとセッションの識別子を検証したうえで、対象の範囲に限り、アクセス頻度を制限する。
- 言語モデルへ渡す情報は、型付きの候補値と集計値に限る。URL・認証情報・ファイル・証拠は渡さない。モデルはスコープ・認証・試行上限を変更できない。
- デスクトップ版の画面は、起動ごとに発行する秘密のトークンを持たない要求を受け付けない。
- 外部の言語モデルへ送るには、明示の許可、API キーを保持する環境変数名、費用の上限が必要。キー自体は保存せず、レポートにも出さない。デスクトップ版の画面で選べるのは、この端末上のモデルだけ。

## 9. 非機能要件

- 動作環境: macOS（Apple Silicon）と Windows（x64）のインストーラー版。ソース版は Node.js 24 以上で、macOS・Windows・Linux。インストーラー版は Node.js を同梱している。
- 実行はすべてローカル。診断の対象、利用者が設定した外部サービス、利用者が操作した導入（ブラウザー、ZAP、Java）の公式配布元以外へ通信しない。
- 長い処理は進捗を表示し、取消ができる。取消・期限・上限で終了した結果は、完了と区別して保存する。
- 画面は 960×648 以上の固定サイズに収まり、長い結果は領域内でスクロールする。
- 言語は日本語・英語・フランス語。教材は日本語と英語。
- ブラウザーの導入以外は、モデルや追加ソフトウェアなしで利用できる。

## 10. 受入基準

- サイトを保存し、テストケース生成がフォーム・ケース・テストコードを出力できる。
- YAML を編集してテストコードを再生成でき、同じセッションでベースラインの記録と比較ができる。
- 動的診断は、許可の確認なしに開始できない。ZAP 連携を有効にすると、警告がテストケースに対応付いて保存される。
- 静的解析は、解析対象に書き込まず、解析結果専用の保存先にだけ結果を保存する。
- サンプル検証は、正常版で違反なし、問題を入れた版で既知の 4 件を再現、修正版で違反なしとなる。
- 遺伝的探索は、問題を入れた版だけで独立再現が成立し、正常版・修正版では再現しない。取消・上限・不正な設定で安全に停止する。
- 3 方式の比較は、修正版でどの方式も再現しない。再現率は有効な実行だけを分母にする。
- OpenVEX は、承認前に書き出せず、承認後は編集できない。検証で何も見つからなかっただけでは「影響なし」が作れない。
- 結果とドラフトは、端末内の非公開領域にだけ保存される。

## 11. 利用上の注意

- 自動検出は、レビューの手がかりであり、脆弱性の確定や安全性の保証ではありません。
- 有限の試行で違反が見つからなくても、対象が安全であることの証明にはなりません。
- 本番環境へ診断する前に、ステージング環境で巡回範囲とページ数を小さくして影響を確認してください。
