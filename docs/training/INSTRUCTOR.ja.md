# 講師用ガイド

[English](INSTRUCTOR.md) · [受講者用](README.ja.md)

## 開始前

Node.js 22 以上、npm、Chromium が使用できることを確認します。全員が別々のローカル環境を使います。サンプルの状態切替はサーバー単位です。会場で一つのサーバーを共有すると、誰かの変更操作が他の受講者へ影響します。

講師は事前に `npm test`、`npm run training:verify`、`npm run training:capture` を通します。後二つは自分でサーバーを起動するため、手動の Hub / サンプルを終了しておきます。撮影は既存の研修サイトに新しい生成セッションを追加し、そのセッションのケースを編集します。既存セッションは更新しません。ポート競合時は既存プロセスを自動停止しません。

受講者は `training:setup` と二つのサーバー起動から開始します。手動で新規登録した場合は、そのサイトを以降の操作で一貫して選びます。英語コースでは URL の `/ja/` を `/en/`、サイト ID を `training-en` にします。

## 進行例

| 時間の目安 | 手順 | 到達確認 |
|---|---|---|
| 0〜10 分 | T01–T02 | 二つのポートの役割を説明でき、デモ申請が完了する |
| 10〜25 分 | T03–T04 | 認証設定と保存シナリオを確認できる |
| 25〜40 分 | T05–T06 | ケースを生成し、人数 5 の 1 ケースへ編集できる |
| 40〜60 分 | T07–T08 | 無変更 PASS → 変更差分 → 修正 PASS を確認する |
| 60〜80 分 | T09–T10 | DAST の追加指摘と SAST の修正前後を説明する |
| 80〜90 分 | T11 | 結果共有と片付け |

時間配分は目安です。初回ダウンロード、端末性能、入力ミスの修正時間は別に見積もります。

## 採点・確認の基準

- T04: パスワードをシナリオに含めず、申請画面へ到達できる。
- T05: フォームが 1 個以上生成され、レポートを開ける。生成時 OK を業務仕様の保証と解釈しない。
- T06: 値は `Demo Learner` / `learner@example.test` / `5`。最初の 1 行を残す。任意項目がないのは正常。
- T07: ベースライン記録と無変更比較の両方がすべて PASS。
- T08: 変更版は差分あり、修正版はすべて PASS。途中でベースラインを更新しない。
- T09: 変更版だけに `DAST-HEADER-CONTENT-SECURITY-POLICY` と `DAST-HEADER-X-CONTENT-TYPE-OPTIONS` が出る（申請画面 1 ページで診断）。
- T10: before は `SAST-DANGEROUS-EVAL` と `SAST-SQL-CONCAT`、after は 0 件。

ローカル HTTP などの指摘が残る理由、パッシブ診断とシナリオ操作によるリクエストの違い、画像差分だけでは判定できない業務要件も説明します。初回と同じ OS / ブラウザー / フォントで比較してください。

## 復旧

シナリオに送信操作まで入った場合は T04 の JSON に戻します。誤ってベースラインを変更版で記録したら、基本版に戻して記録し直し、無変更比較からやり直します。

設定を戻すには `npm run training:setup -- --reset`、サンプルの状態を戻すには `npm run training:mode -- reset`。前者は既存セッションを削除しません。やり直す演習では新しくパイプラインを実行し、最新のセッションを選択してください。

## 受講者から集める記録

使用バージョン、OS・ブラウザー、言語、セッション ID、つまずいた手順 ID、期待したこと、実際のこと、必要なら画像。実在の認証情報・個人情報を記録させません。この記録から、サンプル再現例 → 不具合修正 → 回帰テスト → 日英教材更新につなげます。
